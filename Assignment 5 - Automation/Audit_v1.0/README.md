# IT Work Triage — Audit and Human Review v1.0
Assignment 5 prototype. Synthetic data only. Python 3.13 on Windows. Run install_audit.bat, start_audit.bat, then run_audit_tests.bat in another window. Health: http://localhost:8003/health; interactive interface: http://localhost:8003/docs.

POST /begin reserves a request ID and returns an attempt token. POST /finish records the assessment and moves it to routine_advisory, pending_review or failed. GET /items and GET /items/{id}/events display persistent records. POST /items/{id}/review records accept, reject or override, with justification. Pending review remains held indefinitely; no production action is authorized. Explicit retry of a failed assessment requires the identical payload and retry=true. Stale attempt tokens and changed payloads are rejected.

This service is standalone: n8n integration, reuse of a cached classifier result on retry, recovery of interrupted processing, authentication/role enforcement, retention, backup and tamper-resistant audit controls are not implemented. Reviewer names are self-reported demo identities. SQLite is persistent but not immutable. Keep the service bound to localhost. Do not commit audit.sqlite3 or runtime data. Regression tests use synthetic simulated assessment payloads and unique IDs; they do not exercise live upstream services. The database is created at startup. To verify persistence, restart the API and inspect /items. Never treat an advisory or reviewer decision as production authorization.
